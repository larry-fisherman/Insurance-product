# Review the implemented product

Use `make full-up`, then visit http://localhost:3000/login and open a fictional example. The environment creates a separate agency each time; there is no shared demo password. Synthetic sessions last eight hours and disclose their MFA bypass. To test normal access, register a fictional email, enroll an authenticator, and save recovery codes.

## Workflow checks

- **Agency dashboard:** active submissions, open discrepancies, approved/exported submissions, failures, and upcoming due dates. Counts cover all scoped submissions; the displayed submission list and actionable readiness queue are capped at 100. Filter to your assigned work when needed.
- **Insured accounts:** create/edit legal name, DBA, entity, address, operations, external reference; search; view submission/renewal history. Directory queries are capped and expose a cursor in the API.
- **Submission:** set proposed policy dates, required loss history, due date, responsibility, and renewal lineage. Creating a renewal copies prior reviewed facts as unverified candidates with revision lineage. Confirm their current applicability and dates; no approval is inherited.
- **Documents:** PDF/XLSX uploads, scan quarantine, classification, native parsing/OCR, status/error codes, retries, immutable replacement versions, exclusions with reasons, and original downloads after scanning. An excluded document stays in completeness accounting and all package inventories; an approver must explicitly accept the omission or replacement adequacy.
- **Review:** source blocks display page/line or sheet/range. Exposure context includes basis, role, period, unit, currency, and scope. Nothing is selected in a new material conflict. Approve supported observations; correct with independently supported evidence or an explicit attributed attestation. Omission remains pending until an approver accepts it; rejection is limited to unsupported incorrect extractions. Add broker attestations when information was confirmed outside documents.
- **Missing information:** name, operations, and at least one contextual exposure are required. Every extracted group needs review. Missing coverage/loss requirements may be accepted by an approver with a reason and are included in exports. Missing loss runs never become a no-loss history.
- **Packages:** generate original PDF/XLSX/ZIP; inspect preview, revision, and manifest; approve the exact bytes; export manually. Changing evidence, facts, or material submission settings requires a new package and approval. ZIP includes original supporting files and a snapshot/manifest.
- **Follow-ups:** create, reassign, reschedule, resolve with a reason, or reopen tasks; stale row versions are rejected; agency queue links back to their submission. No external email is sent.
- **Settings:** administrators invite users using expiring manually shared links and assign explicit role bundles. Administrator alone does not provide document/approval access. Last active administrator cannot be removed. Current permissions are checked again on requests.
- **History and measurement:** immutable audit entries record review/approval/export actions without full document text; usage captures processed pages and package generation. Broker-reported baseline/active preparation minutes support pilot time-savings measurements.

## Important limitations to challenge during review

The parser recognizes explicit labels and simple two-column schedules. Complex schedules, carrier-specific formats, complex entity/location relationships, endorsements with operative wording, claims-made variants, multi-entity relationships, and intricate loss reports need a representative authorized corpus and insurance-domain review. The generic model does not infer carrier class mappings or classify insurance appetite.

Source snippets are bounded to 8,000 characters per line/row; inspect the full original for long wording. Parsed documents have a 2,000,000-character text budget and the local extractor allows at most 500 proposed facts per document. Oversized or unsupported inputs require splitting or manual handling. OCR citations identify the page and recognized text line, not a verified pixel-level bounding box. Original files are available for comparison. Unclassified documents, unavailable fields, unassociated source content, truncated excerpts, and unresolved pages require explicit review and any permitted approver-recorded exception before generation, including when other extraction succeeds. This build does not guarantee extraction completeness; all proposals need review, and missing core fields block output. Add an attested field only after independently verifying it.

MVP exports are original summaries; they are not carrier-approved applications or ACORD forms. The software makes no legal or insurance coverage conclusions. External distribution is manual. Operator-managed local retention is not a customer-facing deletion policy.

The default parser performs no paid AI calls. Provider adapters are tested with simulated responses; real models and vendor data handling have not been evaluated. `store:false` is a request parameter, not an assertion about vendor retention.

The standard Compose browser harness uses real API, PostgreSQL, Redis, worker, and storage services with fictional fixtures. The review-remediation acceptance run used temporary PostgreSQL/filesystem storage and a local polling worker, with no external providers. Regression evaluation uses generated explicit-label packets and must not be cited as real-world insurance-document accuracy. See pilot gates before using any customer information.
