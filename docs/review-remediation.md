This records the changes made in response to `review.md`. The repository remains a **local synthetic review build with outstanding functional and release requirements**. Passing the regression suite does not establish the complete MVP or pilot acceptance criteria in `plan.md`.

## Additional functional changes

- Renewals copy the latest immutable prior revision into unverified candidates with prior revision/hash/fact lineage. They inherit no approval or canonical facts. Current evidence or an attributed current confirmation is required. Historical contexts stay visible for correction.
- Audited submission transitions support draft/collection/review/readiness and terminal states. Processing and readiness guard transitions. Closed/cancelled workspaces reject material edits while retaining history.
- Tasks support active-member reassignment, due-date changes, resolution reasons, and optimistic row versions. The dashboard aggregates over all scoped submissions, exposes current readiness blockers, and supports an owner filter; the displayed list/queue remains bounded.
- Cited PDFs can open at their page with browser-dependent search highlighting. Spreadsheet evidence shows actual cells, formats, formulas/cached values, and hidden context. Parse inventory retains merged ranges and hidden rows/columns. Full PDF geometry and a browser-independent highlight overlay remain open.
- Whole-document classification can be corrected with an attributed reason. Automatic segmentation uses explicit page/sheet/heading boundaries; arbitrary mixed tables and segment-level broker overrides remain open.
- Package template `original-cgl-2` adds contextual location/exposure/coverage/loss tables and dedicated XLSX schedules. Correction origins/history, excluded assertions, and complete source metadata remain available. Oversized source metadata and exception messages are split rather than silently truncated into spreadsheet cells. Broker layout/content sign-off remains required.
- Public workspace and principal mutation responses have Pydantic schemas; the frontend consumes generated OpenAPI types. Review forms guard dirty tab/link navigation and browser unload. Precise typing of every remaining identity/list/report route and browser-back navigation handling remain open.
- Parsing is checkpointed before extraction. Jobs use bounded retry backoff, aggregate active PDF-page limits, reproducible extraction-run metadata, and attempt/failure usage events. Provider tokens/costs remain explicitly unknown/unpriced; full cost/budget integration and durable per-page checkpoints remain open.

## Migration and existing workspaces

Apply migrations through `0006_workspace` using the normal local startup/migration commands. Neither migration rewrites immutable observations, decisions, revisions, artifacts, or approvals. Existing observations are marked `legacy_unvalidated`, and affected submissions receive a new input version and an audit event so old packages become superseded. Old corrections require a new support choice. Review legacy facts against their original documents using the new correction controls, or upload replacement versions to rerun extraction. Resolve replacement/exclusion limitations before generating and approving a new package. Historical artifacts remain available only through the existing explicit historical-version acknowledgment.

Migrations were exercised only on disposable PostgreSQL databases. The developer's persisted database and private configuration were preserved.
